# ２−１４★★★★☆　RPGのパーティを、クラス図にする

[課題について](../index.md) ｜ [2章の課題](index.md) ｜ 関連資料：[集約・合成とクラス図](../../s2-ai-state/composition-class-diagram.md)

---

今度はコードがない状態から、クラス図を考えます。題材はよくある RPG のパーティです。下の**仕様を読み、Mermaid 記法でクラス図を書いてください**。コードは書きません。[Mermaid Live Editor](https://mermaid.live/) で図を確かめながら進めます。

### 仕様

---

```text
1. パーティには、キャラクターが最大4人入る。キャラクターはパーティを抜けても消えない
2. キャラクターには、戦士と魔法使いの2種類がある。どちらも名前と HP を持つ
3. 戦士と魔法使いは、どちらも「攻撃できる」。ただし攻撃の仕方は違う（剣で斬る、魔法を撃つ）
4. キャラクターは、作られたときに自分のステータス（攻撃力・防御力）を1つ持つ。キャラクターが消えるとステータスも消える
5. キャラクターは、武器を1つ装備できる。武器は付け替えられ、外した武器は残る
6. キャラクターは、今狙っている敵を知っている。敵はキャラクターの持ち物ではない
```

### 進め方

---

1. 仕様から、クラスになりそうな名詞を拾う（パーティ、キャラクター、戦士、魔法使い、ステータス、武器、敵）。
2. 「攻撃できる」は、種類の違うキャラクターに同じ操作を求める約束なので、Interface にする。
3. 下のひな形を Mermaid Live Editor に貼り付け、`TODO` の部分を書き足す。
4. 図ができたら、仕様の 1〜6 がすべて図に表れているか見直す。

ひな形です。クラス名は英語で書くと Mermaid でエラーになりにくいです。

```text
classDiagram
    class Party {
        +Join(Character character)
        +Leave(Character character)
    }
    class Character {
        +string Name
        +int Hp
    }
    class IAttacker {
        <<interface>>
        +Attack()
    }
    class Warrior
    class Wizard
    class Status
    class Weapon
    class Enemy

    %% 例：仕様2（キャラクターと戦士）
    Character <|-- Warrior

    %% TODO：残りの線を書く
```

### 推奨条件

---

```text
・仕様の 1〜6 を、すべてクラス図の線で表す
・継承、実現、関連、集約、合成をそれぞれ1本以上使う
・Status と Weapon には、仕様に出てくる値をフィールドとして書く
```

### 提出方法

---

Mermaid のコードと、Mermaid Live Editor で表示した図のスクリーンショットをslackに提出してください。課題番号を添えてください。

### ヒント

---

関係の線の向きに迷ったら、講義資料の[関係の線](../../s2-ai-state/composition-class-diagram.md)の表を見ます。三角は親（約束）の側、ひし形は全体（持ち主）の側に付きます。

集約と合成の見分け方は、「全体がなくなったとき、部分も一緒になくなるか」です。仕様の文章の「消えない」「消える」「残る」が手掛かりです。講義資料の `Hero` と `Inventory`・`IWeapon` の例とよく似ています。

多重度（`"1"`、`"0..4"` など）は、余裕があれば書き足しましょう。
